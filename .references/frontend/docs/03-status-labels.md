# قاموس النصوص — لا تظهر أي رموز برمجية للمستخدم

الخادم يتعامل بالأسماء الإنجليزية (يسار)، وكل واجهة تعرض النص العربي فقط عبر دالة واحدة `statusLabel(status, role)`. الكود في النموذج: `prototype/js/techfix.js` (`STATUS`, `ADMIN_ST`, `ITEM_TYPES`, `PAY`, `PAYSTATE`, `VERIF`, `ACCOUNT`, `AVAIL`, `SLOTS`).

## قيم أخرى
- بنود السعر: LABOR = أجر العمل، MATERIAL = خامات وقطع، OTHER = بنود أخرى.
- الدفع: CASH = نقدًا عند الانتهاء، ONLINE = دفع إلكتروني. حالة الدفع: لم يُدفع بعد / مدفوع جزئيًا / مدفوع.
- التوثيق: قيد المراجعة / موثّق / مرفوض. الحساب: نشط / موقوف. التوفر: متاح الآن / مشغول حاليًا / غير متاح.
- الفترات: صباحًا (9 – 12) / ظهرًا (12 – 4) / مساءً (4 – 8).

## قواعد صياغة
- لا مصطلح إنجليزي ولا رمز داخلي (IN_PROGRESS، DVR/NVR، LNB، Escrow، webhook…) في واجهة المنتج. استُبدل: «جهاز التسجيل»، «ضبط إشارة الاستقبال»، «بوابة الدفع».
- أخطاء الخادم تصل برمز (`INVALID_STATE`…) وتُترجم إلى جملة تشرح ما حدث وما يفعله المستخدم (انظر `ERR`).
- الأفعال ثابتة عبر الرحلة: «اختيار هذا المهندس» ← «تم إرسال طلبك»، «موافقة على العرض» ← «تمت الموافقة».
- كل شاشة تحتوي حالات: تحميل، فارغ، خطأ، نجاح.
