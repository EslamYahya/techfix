# 04 — اتفاقيات الـ API

- **الأساس:** `/api/v1` (الإصدار في المسار؛ الكسر يعني v2). العقد الكامل: `openapi.yaml`.
- **النجاح:** `{ "success": true, "data": …, "meta": { "nextCursor", "requestId" } }`
- **الخطأ:** `{ "success": false, "error": { "code", "message", "details": [] } }`
  - `code` رمز ثابت (انظر `src/domain/errors.ts`)، `message` إنجليزي للمطور فقط؛ **الواجهة تترجم الرمز** إلى جملة عربية. لا تعتمد الواجهة على `message`.
- **أكواد HTTP:** 200/201/204؛ 400 صياغة خاطئة؛ 401 غير مصادَق؛ 403 ممنوع؛ 404 غير موجود **أو غير مملوك لك**؛ 409 تعارض/حالة لا تسمح؛ 422 فشل تحقق؛ 429 تجاوز المعدل؛ 500.
- **الترقيم:** مؤشر (cursor) مبهم + `limit` (≤100). لا `offset` على الجداول الكبيرة.
- **التحقق:** كل DTO يُتحقَّق منه (class-validator/zod) قبل الخدمة؛ الحقول غير المعروفة تُرفض.
- **Idempotency:** الرأس `Idempotency-Key` على: إنشاء الطلب، قبول العرض، إنشاء الدفع، تأكيد الإنجاز، تأكيد استلام النقد. التخزين: `(user, route, key) → (body hash, response)` لمدة 24 ساعة. نفس المفتاح والجسم ⇒ نفس الاستجابة؛ جسم مختلف ⇒ 409 `IDEMPOTENCY_CONFLICT`.
- **التزامن:** كل انتقال يستخدم `version`؛ التعارض ⇒ 409، والواجهة تعيد التحميل وتعرض «حدّث الصفحة».
- **الاستجابة الغنية:** `GET /service-requests/:id` يعيد الطلب والخدمة والمهندس/العميل (بعد الإخفاء) والعروض والمهمة والدفع (`PaymentSummary`) والخط الزمني و**`availableActions`**: قائمة بما يستطيع المستدعي فعله الآن (مشتقة من `allowedEvents()` والملكية). هذا يمنع تكرار منطق «ماذا يظهر» في الواجهة.
- **التوقيت:** `date-time` بصيغة ISO-8601 UTC؛ التواريخ المفضلة `date` بتوقيت القاهرة (Africa/Cairo) والفترات `MORNING/NOON/EVENING`.
- **الأمان:** معدّل محدود على الدخول/التسجيل/إنشاء الطلب؛ CORS بقائمة بيضاء؛ `X-Request-Id` يُولَّد ويُعاد.
- **Webhook:** `/payments/webhook` بلا JWT؛ يُصادَق بالتوقيع؛ يرد 200 بعد التحقق دائمًا (حتى للمكرر) كي لا يعيد المزوّد الإرسال بلا نهاية.
