# 07 — الأمان والصلاحيات

## التفويض = صلاحية + ملكية + حالة
الكود: `authorize()` في `src/domain/permissions.ts`. الترتيب ثابت لإخفاء المعلومات:

`401 (لا هوية) → 403 ACCOUNT_SUSPENDED/FORBIDDEN (لا صلاحية) → 404 (ليس مالكها) → ENGINEER_NOT_VERIFIED → 409 (حالة لا تسمح)`

- نستخدم `requirePermission("engineers.verify")` لا `if role === ADMIN`. كتالوج الصلاحيات مطابق لجدول Release v1.
- **الملكية:** العميل: `customerId == profile`. المهندس: `selectedEngineerId == profile` (غير المختار لا يرى الطلب أصلًا). الإدارة: حسب الصلاحية.
- غير المالك يحصل على **404 لا 403** حتى لا تُخمَّن المعرّفات.
- المرجع التنفيذي لكل إجراء: `ACTION_GUARDS` (الصلاحية + الحالات المسموحة). اختبار العقد يتأكد أن كل صلاحية مستخدمة موجودة في الكتالوج.

## مصفوفة (مختصر)
| الإجراء | عميل | مهندس | إدارة |
|---|---|---|---|
| إنشاء طلب / اختيار مهندس | ✅ | ❌ | ✅ (نيابةً، مع تدقيق وسبب) |
| قبول/اعتذار عن طلب، إرسال عرض | ❌ | ✅ (مُسنَد إليه، موثّق) | ❌ |
| قبول/رفض عرض | ✅ | ❌ | ❌ |
| انطلاق/وصول/بدء/إنهاء | ❌ | ✅ | ❌ |
| تأكيد الإنجاز / تقييم | ✅ | ❌ | ❌ |
| تأكيد استلام النقد | ❌ | ✅ | ❌ |
| توثيق/إيقاف مهندس، استرداد، إعدادات | ❌ | ❌ | ✅ |
> Release v1 يضع ✅ للإدارة في عدة إجراءات؛ اخترنا **عدم** السماح لها بقبول عرض أو تنفيذ مهمة نيابةً عن أطراف لأن ذلك يمسّ الإثبات التجاري. تصرّف الإدارة نيابةً عن العميل محصور في الاختيار والإلغاء. (قرار مفتوح لتأكيده.)

## الخصوصية
- العنوان الكامل، الإحداثيات الدقيقة ورقم العميل مخفية عن المهندس حتى `CONFIRMED` (`redactForEngineer`). قبلها: المنطقة والاسم الأول فقط.
- العميل لا يرى هاتف المهندس ولا موقعه الدقيق قبل الحجز؛ لا تتبّع مفتوح. التتبع الحي (لاحقًا) أثناء المهمة فقط وبحدود واضحة.
- ملفات التوثيق في تخزين خاص، روابط موقّعة قصيرة العمر، لا روابط عامة.

## قائمة الأمان الأساسية
HTTPS فقط؛ كلمات المرور argon2id/bcrypt؛ JWT وصول قصير (≈15 دقيقة) + Refresh دوّار مخزَّن hash؛ إعادة استخدام Refresh مُبطَل ⇒ إبطال العائلة؛ حدود معدل (دخول/تسجيل/طلبات/OTP)؛ تحقق مدخلات صارم؛ Prisma معاملات مُحضَّرة (لا SQL مجمَّع إلا `$queryRaw` بمعاملات)؛ رفع ملفات: نوع/حجم/فحص، تخزين كائنات، أسماء عشوائية؛ أسرار من البيئة؛ سجلات تدقيق لكل تغيير مالي/حالة/إداري؛ ماسح للتبعيات.

## تهديدات ومعالجتها
| تهديد | معالجة |
|---|---|
| تلاعب بالسعر من العميل/المهندس | لا حقل total في المدخلات؛ الحساب في الخادم؛ المقبول غير قابل للتعديل |
| دفع مزوّر (إعادة توجيه) | اعتماد webhook موقّع فقط + مطابقة المبلغ + تفرّد الحدث |
| ضغط مزدوج / إعادة إرسال | Idempotency-Key + قفل متفائل + قيود فريدة |
| تخمين معرّفات | UUID + 404 لغير المالك |
| مهندس يلتف على المنصة | إخفاء بيانات التواصل حتى الحجز (السياسة الكاملة مفتوحة) |
| تسريب بيانات بين الأدوار | DTO مختلف لكل دور + `redact*` + اختبارات |
| حساب مهندس مزيّف | توثيق إلزامي قبل أي طلب |
