# 09 — الاختبار وتعريف الاكتمال

## الموجود في هذا المرجع (51 اختبارًا، تعمل بـ `npm test`)
| الملف | يثبّت |
|---|---|
| `state-machine` | المسار الكامل، الاعتذار/المهلة/التغيير، تعديل العرض المرفوض، منع الفاعل/الحالة الخاطئة، قواعد الإلغاء، عدم وجود حالة بلا مخرج |
| `quote` | حساب الخادم بلا انحراف عشري، تجاهل أي total من العميل، رفض المدخلات، العرض الإضافي، عدم تعديل المقبول |
| `matching` | الأهلية قبل الترتيب، BUSY أقل، كسر التعادل، التخصص الفرعي، إخفاء الدرجة، مجموع الأوزان، إعادة الفحص |
| `permissions` | 401/403/404/409، عدم قدرة العميل على إنشاء عرض، غير المالك 404، مهندس غير موثّق، موقوف |
| `payments` | UNPAID/PARTIAL/PAID، الإنجاز ≠ الدفع، webhook (توقيع/تكرار/مبلغ)، النقد بعد الإنجاز، إخفاء العنوان |
| `contract` | تطابق `openapi.yaml` مع الكود، ومع حالات الواجهة التجريبية |

## عند بناء الخدمة الفعلية يُضاف
- **تكامل** (Postgres+PostGIS حقيقي عبر Testcontainers): كل نقطة API: نجاح + 401/403/404/409/422؛ معاملة قبول العرض (فشل إنشاء المهمة ⇒ تراجع)؛ تزامن (انتقالان معًا ⇒ واحد ينجح)؛ استعلام الترشيح.
- **Webhook:** توقيع صحيح/خاطئ، تكرار، ترتيب معكوس، مبلغ مختلف.
- **Idempotency:** تكرار قبول العرض والدفع.
- **أمان:** محاولات ملكية مضادة لكل مورد؛ اختبار عدم ظهور العنوان/الرقم في JSON المهندس قبل CONFIRMED.
- **E2E** يعكس سيناريو النموذج التجريبي: طلب → ترشيح → اختيار → قبول → عرض → قبول → نقدًا → رحلة → إنجاز → تأكيد → استلام نقد → تقييم؛ وسيناريو الدفع الإلكتروني والعرض الإضافي والبلاغ.
- **المهام الدورية:** المهلة، انتهاء العرض، المصالحة.

## تعريف الاكتمال (لكل ميزة)
قاعدة مثبتة باختبار؛ تفويض كامل (صلاحية+ملكية+حالة)؛ تدقيق؛ أخطاء برموز؛ مدخلات متحقَّقة؛ ضمن معاملة عند اللزوم؛ مسجَّلة في `openapi.yaml`؛ لا تسرّب بيانات بين الأدوار.
