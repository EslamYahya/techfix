# 12 — ترتيب البناء المقترح

1. **الأساس:** مشروع NestJS، Prisma، migration أولى + `postgis.sql`، إعدادات، سجلات، `X-Request-Id`، مغلّف الاستجابة والأخطاء (`DomainError`⇄HTTP).
2. **auth + users:** تسجيل/دخول/تجديد/خروج، حارس JWT، `authorize()`؛ بذور: مشرف، الفئات والخدمات.
3. **المهندس:** الملف، التخصصات، الموقع (PostGIS)، التوفر، رفع الوثائق؛ **admin:** التوثيق والإيقاف.
4. **الطلبات + المطابقة:** إنشاء، `recommendations` (استعلام PostGIS)، `select/change-engineer`، قبول/اعتذار؛ مع `request_events`.
5. **العروض:** إنشاء/قبول/رفض؛ معاملة القبول وإنشاء Job.
6. **المهمة:** انطلاق…تأكيد الإنجاز، العرض الإضافي، البلاغ.
7. **المدفوعات:** نقدًا ثم الإلكتروني (Provider + webhook + idempotency + المصالحة).
8. **التقييم + التجميعات.**
9. **الإشعارات + الطوابير + outbox + المهام الدورية.**
10. **الإدارة:** الطلبات، الماليات، الإعدادات، النزاعات، إشراف التقييمات.
11. **التقوية:** حدود المعدل، تدقيق كامل، اختبارات تكامل/E2E، مراقبة، نسخ احتياطي.
12. **بعد الإطلاق:** المتجر (المرحلة 2)، المحفظة والعمولات، التتبع الحي، الدردشة (المرحلة 3).

> بعد كل خطوة: شغّل نموذج الواجهة التجريبي على الخادم الحقيقي (استبدال `TF.A.*` بطلبات `fetch`) وتأكد أن نفس السيناريو يمر.
